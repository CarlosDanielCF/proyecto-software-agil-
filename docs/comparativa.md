\# 📊 Comparativa de Metodologías y Estudio de Casos



\## 1. Cuadro Comparativo: Tradicionales vs. Ágiles



| Aspecto                  | Metodologías Tradicionales (Cascada)                                      | Metodologías Ágiles (Scrum)                                           |

| ------------------------ | ------------------------------------------------------------------------- | --------------------------------------------------------------------- |

| \*\*Manejo de requisitos\*\* | Se definen al inicio, se busca minimizar cambios.                         | Se aceptan y aprovechan los cambios.                                  |

| \*\*Ciclo de vida\*\*        | Fases: Análisis → Diseño → Codificación → Pruebas → Implantación.         | Sprints cortos (1–4 semanas), con un ciclo repetido en cada Sprint.   |

| \*\*Entrega\*\*              | Una sola entrega al final del proyecto.                                   | Entrega continua de software funcionando.                             |

| \*\*Documentación\*\*        | Exhaustiva y detallada al inicio.                                         | Esencial y necesaria; el software es la principal fuente.             |

| \*\*Rol del cliente\*\*      | Participa al inicio y al final; poco involucrado durante el desarrollo.   | Colabora continuamente y proporciona retroalimentación en cada ciclo. |

| \*\*Ventajas\*\*             | Estructura clara, predecible y fácil de gestionar.                        | Rápida adaptación, valor temprano y menor riesgo.                     |

| \*\*Desventajas\*\*          | Difícil adaptarse a cambios; el valor se obtiene principalmente al final. | Menor previsión a largo plazo; requiere disciplina.                   |



\## 2. Estudio de 3 Casos Reales



\### ✅ Caso 1: Sistema de Inventarios Estable



\* \*\*Características:\*\* Requisitos definidos, alcance estable y funcionalidad conocida.

\* \*\*Metodología:\*\* Cascada (Tradicional).

\* \*\*Justificación:\*\* Los requisitos no cambiarán significativamente. Se puede planificar todo el ciclo con anticipación. La previsibilidad es más importante que la adaptación.



\### ✅ Caso 2: Plataforma de Comercio Electrónico en Evolución



\* \*\*Características:\*\* Mercado cambiante, competencia, requisitos evolutivos e innovación continua.

\* \*\*Metodología:\*\* Scrum (Ágil).

\* \*\*Justificación:\*\* Se necesita entregar valor incrementalmente, recibir retroalimentación y adaptarse rápidamente. Si se esperara hasta el final, el producto podría dejar de ser competitivo.



\### ✅ Caso 3: Software Médico Regulado



\* \*\*Características:\*\* Normativas estrictas, documentación obligatoria, certificaciones y trazabilidad total.

\* \*\*Metodología:\*\* Híbrida (Cascada + elementos ágiles internos).

\* \*\*Justificación:\*\* Las regulaciones exigen planificación previa y documentación completa. Se pueden desarrollar módulos de forma ágil internamente, pero respetando los requisitos normativos definidos al inicio.



\---



\## 3. Principios Ágiles Aplicados al Comercio Electrónico



\### Principio 1 — Entrega continua de valor



> Entregar una versión funcional cada 2 semanas. El cliente valida y orienta el siguiente ciclo.



\### Principio 2 — Aceptar los cambios



> Los nuevos requisitos del mercado se integran en el siguiente Sprint sin reiniciar todo el plan.



\### Principio 3 — Software funcionando = medida de progreso



> Al final de cada ciclo se demuestra la aplicación en vivo. La documentación no representa por sí sola el avance; el software funcionando es la principal medida de progreso.
